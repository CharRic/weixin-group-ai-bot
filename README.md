# Weixin Group AI Bot

一个运行在 Linux 容器桌面中的微信群 AI 助手。它读取本机微信数据库，只响应真实的群聊 `@`，并通过桌面 UI 把回答发回原群。

## 主要能力

- 自动发现当前账号加入的群聊，不维护固定群白名单。
- 只处理消息元数据中真实 `atuserlist` 包含机器人账号的消息，文本里手写昵称不会触发。
- 每个群独立保存游标、待回复队列、摘要和对话历史，避免跨群混用上下文。
- 单群上下文预算默认为 12,800 tokens；超出预算后滚动压缩旧消息，并把摘要带入后续会话。
- 发送前后校验目标群、窗口标题与数据库落库结果；路由不确定时停止发送。
- 支持 `preview` 模式，确认行为正确后再切换为 `send`。
- 图片由 `deepseek-v4-flash-vision-exp` 提取文字和关键信息，再把文字摘要交给 `deepseek-v4-flash` 结合当前群上下文回答；历史压缩也使用 Flash。
- 全局回复风格在 `persona.txt`：像熟悉的群友一样自然接话，不主动使用助手腔；直接询问真实身份时如实回答。日常默认一两句；方案、攻略、教程等按需展开，严肃话题认真回应。
- 磁盘成员档案与群内风格：从启用后的群发言增量学习，按群/稳定成员标识隔离，回复时按需读取当前提问者与相关成员的必要信息；不把整个特性库常驻内存。
- 每次回答注入实时北京时间；通过只读天气工具获取当前天气和未来七天预报。缺少城市先追问，不猜用户位置。
- `search_stickers` / `send_sticker` 使用微信原生表情搜索和爱心收藏，发送原生表情（含动图），不是只输出emoji。

## 成员记忆与群内人设

`social_memory_enabled` 开启后，全局 `persona.txt` 定义整体回复风格。每群的 `group.md` 只调整语气、幽默、详略和节奏；每位有可学习新发言的成员有独立 MD。目录使用群与成员 ID 的摘要值，不按昵称命名，所以同名、改名不会混档，同一个人在不同群也不互通。

```text
social-memory/                 私有运行数据，已加入 .gitignore
  queue.sqlite3                增量待整理队列、停记设置、更新版本
  <群ID摘要>/
    group.md                   本群风格与待观察候选
    <群内成员ID摘要>.md        明确自述/交流观察、原文短引句、来源编号和时间
```

从首次启用时间起处理新文本发言（普通未艾特文本也可学习，但不会触发回复）；不全量回扫旧记录，不对图片/语音额外做画像识别，不学习机器人自身发言。原始待整理文本每条最多 1,000 字，每群最多 2,000 条、最多保留七天，处理后删除；运行态只保留当前有界批次和当前请求资料，无全库内存缓存。Markdown 是磁盘主档，文件权限 600、目录 700，不进入 GitHub，也不上传全部特性库。整理调用现有 Flash 接口，仅提供本群本批次及相关旧档案摘要；内存使用不可能为零，但不会随全部档案线性增长。

默认每群累积 40 条新文本或最旧待处理文本等待六小时后整理。明确自述、称呼/偏好、更正等线索会提前触发，后台每 15 秒检查一次；失败五分钟后再尝试，正常聊天不会等待整理完成。每次模型输入有字符上限，最多涉及八人。成员每档最多四个分类槽：称呼、兴趣、交流偏好、粗粒度职业背景，每槽要点最多 100 字、合计 400 字，连同来源证据和元数据文件最多 16,000 字节。群风格文件最多 4,000 字节。更新是合并替换、滚动整理，不逐次追加日志；新的明确纠正替换同类旧项。这是小型摘要档案，不是完整人物传记。

只接受本人消息的原文证据，不采纳他人转述为本人事实，不从一句玩笑推断长期性格；交流观察至少三条不同消息支持。排除敏感身份、健康、联系方式、财务等信息（规则过滤加模型约束，并非完美的语义识别）。事实与观察分别标记，明确自述 180 天、观察 30 天后不再带入回答；过期项在下一次该成员档案整理时淘汰。群风格需至少三人六条消息支持，且两个独立批次建议一致才采用，30 天未更新就回落全局风格。学习内容始终作为低优先级引用资料，不拼成新的高优先级系统命令。

回复按当前群和真实发送者 ID 读取提问者档案，并带上本群风格及最多三名相关成员的档案。相关性依次来自真实艾特元数据、在本群数据库核实的引用消息作者、完整本群成员名册中无歧义的姓名提及；不会仅按最近说过话就加载，昵称有歧义或名册不可用时不猜自然语言姓名。短期历史附带群内稳定说话者键帮助区分同名成员。成员适应资料合计最多 2,600 字符，并计入 12,800 上下文预算，必要时舍弃，不能挤掉提问。日常不播报更新、不展示人物清单、不说“根据你的画像”；问及记忆时如实说明，不伪装成从未记录。

成员可真正艾特机器人后发送以下准确指令，程序直接绑定本人、本群处理，不经模型授权：

- `查看我的记忆`：查看本群仍有效的个人摘要。
- `忘记我` / `删除我的记忆` / `不要记住我` / `停止记录我`：删除本人 MD、待整理文本并停记，同时重置可能包含其贡献的本群风格；在途整理结果作废，不能恢复已删档案。
- `恢复记忆` / `可以记住我`：只重新收集此后的发言，不回扫旧消息。

这些操作不删除微信原始聊天、不清空既有会话压缩摘要或短期上下文，也不改变其他群设置。配置开关关闭后不会读取或更新特性库，既有磁盘文件保留。上线前应由运营者向群成员提供可查阅的功能说明与退出方式；无感交互不等于否认记录。

## 微信原生表情工具

在群里真正艾特机器人，例如“给我发个很生气的表情包”或“从收藏里发个开心的表情”。模型先搜索，视觉模型识别面板中的候选，程序绑定本群发送；模型不能传入其他群ID、网址或任意文件。每条提问最多一张，只有本群数据库出现新的自身表情消息才返回`confirmed`，不确定时不自动重发。

无需明确要求表情：被调侃、接梗、轻微尴尬或表达心情时，模型可在纯文字、纯表情、短句加表情中选择；严肃求助、伤心、争吵及事实查询优先文字。仍只响应真实`@`，不会因群里出现某个词就主动插话。没有时间冷却；按群避免连续两次主动发表情，明确索要表情可连续发送。单轮仅搜索一次，失败不重试。`send_sticker`的`reply_mode=sticker_only`在确认送达后直接结束，不再追加“已发送”；`with_text`保留一句自然补充。发送记录与交替规则均按群隔离。

搜索使用微信当前的在线结果，不需要模型生图或预先下载素材库。收藏使用本微信账号爱心页已有资源，空库时会提示并可转用搜索。这版尚未实现从群聊自动添加收藏，不会宣称已经自动收集。原生搜索结果无需维护本地每日下载任务。

表情发送只使用微信原生搜索和收藏，不保留本地图库、外部素材下载、图库更新任务或静态图片发送兜底。`sticker_jobs` 仅记录发送状态、防止重复发送，不存储图库；微信客户端自己的缓存、收藏及群聊历史不受影响。

`stickers_enabled` 控制开关。将 `bot_ui/native_stickers.py` 与 `bot_ui/ui.py` 一起部署到 `/config/bot-ui/`；当前原生表情布局经过 980×710 微信窗口验证，其他尺寸会停止操作。只有表情面板截图送给视觉模型，不包含外围群聊消息。每次新搜索使旧选择失效；发送前核验群标题、活动表情窗口、搜索词和面板位置。

## 时间与天气

可问“现在几点了”“今天星期几”“北京明天天气怎么样”。时间来自已校时服务器，默认注明北京时间；天气来自 [Open-Meteo 预报 API](https://open-meteo.com/en/docs)，按日期选择预报并注明来源。未知或重名城市会追问，接口失败不编造天气。它不是通用联网搜索，不能据此查询任意实时新闻。

天气功能只向固定天气接口传递城市查询和坐标，不上传群历史。模型工具调用仍仅接收当前群的上下文，没有跨群位置记忆。工具结果计入上下文预算，最多两次查询，公共天气数据短暂缓存十分钟。需要兼容不支持工具调用的模型时，可设置 `realtime_enabled: false`；时钟注入仍保留。

## 群聊和图片用法

所有本机已同步、仍在其中的群都会动态加入处理，没有固定两群限制。请在目标群真正艾特机器人；普通未艾特消息不会主动回复。尚未同步到电脑端的群需要先在该群产生消息并完成客户端同步。重名群仍会停止发送，避免发错群。

图片支持两种触发方式：

1. 发图后两分钟内，由同一位成员艾特机器人提问（最多关联最近三张图）。
2. 引用当前群的一张图片，并在引用回复中艾特机器人。引用消息按服务端消息 ID 在本群查找，可引用较早的图片。

图片识别结果按群、消息分片和消息 ID 单独缓存。当前群的图片摘要会进入当前群历史和后续压缩摘要。模型不会收到其他群的图片；图中文字和图片摘要均作为引用资料处理。

本机图片通常是 V2 加密 `.dat` 文件。程序验证账号级图片密钥，优先读取已下载原图，必要时退回缩略图（回复资料中会注明）。本版本在 Linux kvcomm 派生密钥的客户端上验证；不同客户端版本可能需要私有 `image_keys.json`。未下载、解密失败或不支持的图片格式会明确说明无法识别，不会把占位符当成看过图片。暂不支持语音和视频识别。

`bot.json` 中 `system_prompt_file` 指向 `persona.txt` 时，它优先于内联的 `system_prompt`。修改后仅重启机器人子服务即可，无须重启微信或容器。不要在配置变更后直接用容器重建代替机器人子服务重启。

> 这是非官方的实验项目。微信客户端、数据库结构和 UI 随版本变化，自动化可能失效。请只在自己的账号与设备上使用，并遵守适用的服务条款和法律。

## 目录


## 环境要求

- Linux amd64 主机
- Docker Engine 与 Docker Compose v2
- Python 3.10+（用于初始化数据库密钥和运行测试）
- 一个 OpenAI-compatible Chat Completions API

## 快速开始

```bash
git clone https://github.com/CharRic/weixin-group-ai-bot.git
cd weixin-group-ai-bot
cp .env.example .env
cp ai.json.example ai.json
cp bot.json.example bot.json
chmod 600 .env ai.json bot.json
docker compose up -d
```

端口只绑定到 `127.0.0.1`。从另一台电脑访问桌面时，应使用 SSH 隧道，例如：

```bash
ssh -N -L 18080:127.0.0.1:18080 your-user@your-server
```

浏览器打开 `http://127.0.0.1:18080`，登录容器桌面并在微信中完成登录。不要把这两个端口直接暴露到公网。

随后在项目目录创建虚拟环境并提取当前账号数据库所需的密钥：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python wechat_db.py
```

把自己的微信 ID 写入 `bot.json` 的 `bot_id`。先保持 `"mode": "preview"`，观察日志确认只捕获预期消息；确认无误后再改为 `"mode": "send"`，并仅重启机器人子服务或等待其自动拉起。

```bash
docker compose logs -f desktop
```

配置文件包含 API 密钥和账号信息，运行数据包含群名与消息内容。它们均已列入 `.gitignore`，不要手动提交。

## AI 配置

`ai.json` 使用 OpenAI-compatible 接口：

```json
{
  "base_url": "https://api.example.com",
  "api_key": "your-key",
  "model": "your-model",
  "max_tokens": 1024,
  "thinking": "disabled"
}
```

如果服务商不支持 `thinking` 参数，可从配置中删除它。

## 测试

```bash
python3 -m unittest -v
```

测试覆盖真实艾特过滤、动态群发现、群级上下文隔离、滚动摘要，以及多项防串群发送校验。

## 安全说明

- 机器人以只读方式复制并解密微信数据库快照，不会修改微信数据库。
- UI 自动化天然比官方 API 脆弱；重复群名、窗口识别失败或发送确认异常时采用 fail-closed 策略。
- 在提交或分享日志前，先清理微信 ID、群 ID、群名、消息、API 密钥和数据库密钥。
